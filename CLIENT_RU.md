# Консольный клиент

Основная платформа — Windows. Клиент устанавливается вместе с дополнительными зависимостями:

```powershell
python -m pip install -e ".[client]"
silero-tts console
silero-tts speak "Привет, мир"
silero-tts speak --voice aidar --speed 1.2 "Проверка голоса"
silero-tts server --host 127.0.0.1 --port 8000
```

Без подкоманды `silero-tts` по-прежнему запускает сервер. Старые серверные параметры также поддерживаются. Справка: `silero-tts --help`, `silero-tts console --help`.

## Подключение и жизненный цикл

По умолчанию клиент использует `http://127.0.0.1:8000`. Если локальный HTTP-сервер не запущен, клиент запускает его текущим интерпретатором Python. Удалённые серверы и локальные HTTPS-серверы автоматически не запускаются.

```powershell
silero-tts console --url http://127.0.0.1:8080
silero-tts console --url https://tts.example.org --no-start
```

Адрес задаётся без `/v1`. Клиент проверяет `GET /health`: код 200, идентификатор `silero-openai-tts`, состояние `ready` и флаг серверного воспроизведения. Старый сервер без этого endpoint нужно обновить. Если порт занят посторонним приложением, клиент завершится с ошибкой; другой порт автоматически не выбирается.

При `exit`, Ctrl+C и ошибке клиент останавливает только запущенный им сервер. Сначала используется приватный канал штатного завершения, через 8 секунд — принудительная остановка. Windows Job Object завершает принадлежащий клиенту сервер и его дочерние процессы при закрытии лаунчера. Чужой, ранее запущенный сервер клиент не останавливает.

Серверное и клиентское воспроизведение используются раздельно. Если у существующего сервера включён `AUTO_PLAY` или `FORCE_PLAY`, клиент попросит отключить их. В автоматически запущенном сервере эти параметры и `SHOW_TEXT` выключены через окружение только дочернего процесса.

## Настройки

Файл по умолчанию: `%APPDATA%\silero-tts\client.json` на Windows, `${XDG_CONFIG_HOME:-~/.config}/silero-tts/client.json` на Linux/macOS. Можно указать другой файл через `--config <путь>`.

Приоритет: CLI → переменные окружения → JSON → значения по умолчанию. Переменные имеют префикс `SILERO_CLIENT_`: например, `SILERO_CLIENT_URL`, `SILERO_CLIENT_API_KEY`, `SILERO_CLIENT_READ_TIMEOUT`.

Пример JSON:

```json
{
  "url": "http://127.0.0.1:8000",
  "voice": "eugene",
  "speed": 1.0,
  "device": null,
  "connect_timeout": 3,
  "read_timeout": 120,
  "startup_timeout": 120
}
```

Голос, скорость и устройство автоматически сохраняются между запусками. API key и параметры подключения из CLI/окружения автоматически не записываются. Ключ можно передать через `SILERO_CLIENT_API_KEY`, `--api-key` или явно записать в поле `api_key` JSON. При включённой серверной авторизации используется Bearer token.

`--connect-timeout`, `--read-timeout`, `--startup-timeout` задаются в секундах. Автоматически повторяется не более одного сбоя установки соединения до передачи запроса. После таймаута чтения, ошибки ответа или разрыва во время передачи синтез не повторяется.

## Звук и команды

По умолчанию используются голос `eugene`, скорость `1.0` и системное устройство вывода. Скорость: от `0.25` до `4.0`; изменение скорости требует FFmpeg на сервере. Аудио для воспроизведения — WAV.

| Команда | Назначение |
|---|---|
| `/voice <имя> [текст]`, `/v` | Выбрать голос и при необходимости произнести текст |
| `/voices`, `/list` | Список голосов |
| `/speed <число>` | Изменить скорость |
| `/devices` | Список устройств и текущий выбор |
| `/device <номер>` | Выбрать устройство из текущего списка |
| `/device default` | Вернуться к системному устройству |
| `/monitor on`, `/monitor off` | Включить или выключить дублирование в системные динамики/наушники |
| `/monitor` | Переключить дублирование |
| `/status` | Адрес, доступность сервера и текущие настройки |
| `/help` | Справка |
| `exit`, Ctrl+C | Завершить клиент и принадлежащий ему сервер |

Устройство сохраняется по имени и аудиосистеме, а не по нестабильному номеру. Через CLI можно указать полное имя из `/devices`: `--device "Динамики [Windows WASAPI]"`. Если сохранённое устройство недоступно, клиент показывает список и предлагает выбрать другое. Без интерактивного терминала такой случай завершается ошибкой. При одинаковых именах устройств выбор при следующем запуске может потребоваться снова.

Обратная озвучка включается через `/monitor on` или `--monitor` и сохраняется между запусками (`monitor: true` в JSON, `SILERO_CLIENT_MONITOR=true` в окружении). По умолчанию она выключена; CLI-флаг `--no-monitor` отключает её. Основное устройство продолжает получать звук, а клиент одновременно дублирует его в системное устройство вывода. Если основное устройство уже системное, фраза звучит один раз. Серверный `FORCE_PLAY` включать не нужно: оба аудиопотока создаются клиентом и останавливаются по Ctrl+C. При недоступном системном устройстве выводится ошибка.

Ввод остаётся построчным, максимум 4096 символов на запрос. Чтение файлов/stdin и многострочный режим не добавлены. В этой версии ввод ожидает завершения воспроизведения; очередь фраз запланирована следующим этапом. Ctrl+C завершает программу на любом этапе, а не возвращает приглашение.

## Опциональное сохранение аудио

По умолчанию клиент не сохраняет WAV. Для разовой озвучки:

```powershell
silero-tts speak --output greeting.wav "Привет"
```

Файл сохраняется и воспроизводится. Существующий файл не перезаписывается. Серверный кэш работает независимо от этой опции. Режим «сохранить без воспроизведения» и постоянная запись всех фраз не добавлены.

## Совместимость и диагностика

`python run_tts.py` и `run_tts.bat` открывают консоль; аргументы текста запускают разовую озвучку. `python speak.py` использует только существующий сервер. Автосоздание ярлыка для `run_tts.py` сохранено; реализация находится в `app/client/shortcut.py`.

Коды завершения: `0` — успех/обычный выход, `1` — ошибка, `2` — неверные аргументы, `130` — Ctrl+C. В интерактивном режиме ошибка отдельной фразы выводится в консоль, после чего ввод продолжается.

Логи находятся рядом с конфигурацией в `logs/client.log` и `logs/server.log` (последний — для автоматически запущенного сервера). Ротация: 1 МБ для клиента, 2 МБ для сервера, по три архивных файла. Клиент не записывает текст фраз и ключи в лог; у дочернего сервера отключён вывод текста. Существующий внешний сервер управляет собственными логами.

Основная логика: `app/client/config.py`, `session.py`, `launcher.py`, `server.py`, `jobobject.py`. Проверки клиента и жизненного цикла: `python -m pytest tests/test_client.py -q`.
